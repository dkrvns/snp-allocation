# 05. Presentation и API

Применяется к HTTP/gRPC/CLI-границам, схемам, маршрутам и startup.
FastAPI и Dishka используются только в проекте, где они выбраны.

## Граница транспорта

- Endpoint принимает и валидирует форму входа, вызывает одну согласованную
  операцию и переводит результат в ответ. SQL, хэширование и бизнес-политики
  не размещаются в роутере.
- Для бизнес-операции вызывай application Command/Interactor; для технического
  auth-сценария — handler подсистемы infrastructure/auth. Разница указана в разделе 02.
- HTTP-схемы — Pydantic-модели presentation, settings — отдельные модели Config.
  Pydantic и framework-типы не становятся внутренними application/domain DTO.
- Проверяй длины, форматы, обязательность, лишние поля и общий размер тела
  до неограниченной буферизации. Внутренние инварианты проверяются операцией/domain.
- Валидируй все внешние границы, включая ответы upstream API и сообщения очереди;
  статическая аннотация не валидирует полученный JSON.

## HTTP-контракт

- Следуй принятому URL-стилю. Для нового CRUD API предпочитай ресурсы `/orders`,
  `/orders/{order_id}`; не переименовывай существующие auth routes ради формального REST.
- Создание ресурса — 201; успешный bodyless ответ — 204 без JSON body.
  Используй `status.HTTP_*` вместо магических чисел в FastAPI-коде.
- Аннотируй возврат и явно отображай DTO в response schema. Не возвращай ORM entity.
- Пустой DTO чтения проверяется по identity: при отсутствии ресурса endpoint
  отдаёт подходящий 404; для недопустимой identity auth-сценарий отказывает в доступе.
- Application/domain errors переводятся в транспортные ответы централизованно.
  Внутренний слой не поднимает HTTPException. Локальный catch нужен только
  при особом контракте конкретной операции.
- Ошибки стабильны и кратки. Валидация не должна возвращать пароль/токен/code
  в поле input, текст SQL, stack trace или весь upstream response.
- OpenAPI должен описывать реальные request/response schemas, security scheme
  и пригодные примеры. Login JSON не называй OAuth2 password flow, если он им не является.
- UI должен объяснять ограничения формата и длины до отправки. Rate limit,
  доступ и проверка credentials остаются на сервере; disabled-кнопка их не заменяет.

## FastAPI, lifecycle и наблюдаемость

- `create_app()` собирает приложение, маршруты, middleware, DI и обработчики ошибок.
  Тесты вызывают ту же фабрику. Lifecycle закрывает pools, clients и контейнер DI.
- Один связный router на область. Декоратор route расположен выше `@inject`.
  Auth dependencies определяют текущую identity, а не доверяют user_id из body.
- Host/port/concurrency берутся из Config. Секреты не создаются при импорте модуля;
  неподходящая конфигурация даёт понятный отказ запуска без вывода её содержимого.
- Логи содержат request ID, тип операции, статус и длительность, без credentials
  и высококардинальных секретных labels. Ошибки коррелируются между границами.
- Настрой ограничения тела, времени обработки, workers и соединений. Forwarded
  headers принимаются только от явно доверенных proxy, иначе IP-лимиты обходятся.
- При cookies задай явный CORS allowlist, credentials policy и CSRF-защиту.
  Не включай wildcard credentialed CORS для исправления интеграции.

## Другие транспорты

Для CLI и consumers сохраняй ту же тонкую границу: вход → DTO → операция → вывод.
Для gRPC используй сгенерированные типы только на transport-границе, явное
отображение UUID и централизованное соответствие ошибок status codes.
Не подключай HTTP-сервис или gRPC только потому, что для них есть правила.
