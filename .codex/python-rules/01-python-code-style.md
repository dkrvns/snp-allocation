# 01. Стиль Python-кода

Применяется к Python-файлам. Структура responsibilities описана в разделе 03.

## Форматирование и имена

- Ruff, длина строки 88, одинарные кавычки, LF. Сложные сигнатуры и вызовы
  переноси по аргументу на строку с завершающей запятой.
- Импорты: stdlib → third-party → пакет проекта. Используй абсолютные импорты
  из определяющего модуля, без wildcard и цепочек совместимых реэкспортов.
- `Sequence`, `Mapping`, `AsyncIterator`, `Callable` и другие ABC импортируй
  из `collections.abc`. Импорт typing оставляй для его собственных конструкций.
- Модули и функции — snake_case, классы — PascalCase, константы — UPPER_SNAKE_CASE.
  Параметры identity называй `<entity>_id`, а не `id`; не затеняй built-ins.
- Имена объясняют действие: `CreateOrderCommand`, `GetOrderInteractor`,
  `UserGateway`, `UserReader`, `TokenIssuer`. Не используй `Manager`, `Helper`,
  `Processor` и `use_cases` как замену конкретной ответственности.

## Типизация и Python 3.14

- Аннотируй параметры и возврат, включая `-> None`, тесты и вложенные callbacks.
  Используй `list[T]`, `dict[K, V]`, `T | None`, PEP 695 generics и type aliases.
  `Any` допустим только на действительно нетипизированной границе, затем валидируй.
- В Python 3.14 не добавляй `from __future__ import annotations` и кавычки вокруг
  аннотаций без необходимости. Значения, создаваемые во время выполнения,
  всё равно должны быть доступны: ленивые аннотации не откладывают обычный код.
- Для обычного переопределения базовой реализации используй `typing.override`.
  В конкретных gateways, реализующих Protocol-порты, `@override` не добавляй.
- Допустим `except OSError, ValueError:` без `as` при target 3.14.
  При захвате исключения необходимы скобки: `except (OSError, ValueError) as exc:`.
- UUID identity генерируются через внедряемый IdGenerator; базовая реализация
  использует `uuid.uuid7`. Случайность, время и генераторы не прячутся в бизнес-коде.
- Деньги — Decimal или целые минимальные единицы с валютой; не создавай Decimal
  из float. Моменты времени — timezone-aware UTC; календарная дата хранится отдельно.

## Данные и функции

- Между внутренними слоями передавай typed dataclasses с `slots=True`, а не
  словари, ORM-модели или HTTP-схемы. Для immutable DTO — `frozen=True`, для
  изменяемых значений — `field(default_factory=...)`; секретные поля — `repr=False`.
- Словари допустимы на JSON, SQL и других внешних границах. Сразу преобразуй
  внешние данные в проверенный контракт. Rich domain model имеет свои инварианты.
- У функции одна ответственность. Предпочитай ранний возврат глубокой вложенности.
  Зависимости приходят через `__init__`; объект не создаёт собственный DB-клиент
  внутри операции. Простую чистую функцию не оборачивай в класс без причины.
- F-строки подходят для обычного текста. SQL параметризуется средствами драйвера,
  HTML экранируется; f-string и t-string сами по себе не обеспечивают эту защиту.
- Async-код не блокирует event loop. Блокирующий I/O и CPU-нагрузка выносятся
  в ограниченные workers; ресурсы, задачи и соединения закрываются при ошибке
  и отмене. Не делай бесконечные очереди или retries.

## Ошибки и комментарии

- Перехватывай конкретные ожидаемые ошибки. Не используй bare except,
  `except Exception: pass` или продолжение после нарушения инварианта.
- Обычно сохраняй причину через `raise AdapterError(...) from exc`.
  На чувствительной границе проверь, не содержит ли цепочка исключений пароль,
  токен, SQL-параметры или адрес получателя. Публичный ответ и логи санитизируются;
  `from None` допустим при обоснованном сокрытии чувствительной причины.
- Сообщения API и внутренних ошибок — короткие, стабильные, на английском.
  Пользовательский интерфейс может отображать локализованное объяснение.
- Комментарий объясняет ограничение или решение. Не оставляй закомментированный
  код и пересказ очевидных строк. Docstring нужен для публичного контракта
  и нетривиальной функции, а не для каждой одноимённой обёртки.
